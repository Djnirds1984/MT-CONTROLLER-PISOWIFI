Two cooperating deployment targets share one installed layout under `/var/www/aircoins`:
- `scripts/install-sbc.sh` is the idempotent entry point: it detects arch/OS/PHP, installs packages, copies `hotspot/`, `admin/`, `includes/`, `api/` into `/var/www/aircoins/{portal,app/{admin,includes,api}}`, writes a self-contained lighttpd config (`deploy/lighttpd/aircoins.conf`) and a dedicated php-fpm pool (`deploy/php-fpm/aircoins-pool.conf`) via `sed` placeholder substitution (`@@PORTAL_DOCROOT@@`, `@@ADMIN_DOCROOT@@`, `@@API_DIR@@`, `@@FPM_SOCKET@@`, `@@FPMVER@@`), generates a self-signed TLS cert at `/etc/lighttpd/certs/aircoins.pem`, creates a sodium key at `/etc/aircoins/secret.key`, initializes the SQLite DB under `/var/lib/aircoins`, and optionally creates the first admin user.
- `scripts/update-portal.sh` is a lightweight re-syncer that rsyncs only changed directories and reloads php-fpm when PHP code changes.
- `mikrotik/hotspot-external-portal.rsc` is a RouterOS v6/v7 script configuring the router-side half of the redirect flow (DHCP, hotspot profile with `login-by=http-pap,cookie`, walled-garden allowing unauthenticated access to the SBC on port 80, IP binding bypass for the SBC, REST/Legacy API enablement, static DNS).
Dependency direction is one-way: scripts depend on the repo's source trees (`hotspot/`, `admin/`, `includes/`, `api/`) and on the sibling deploy configs; nothing in this module depends on runtime application code beyond invoking PHP for schema/admin creation.
