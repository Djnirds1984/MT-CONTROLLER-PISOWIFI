Two cooperating layers share one set of HTML templates:
- Router-native mode: MikroTik's built-in HTTP server serves `hotspot/*.html` and substitutes `$(var)` tokens (mac, ip, user, link-login-only, etc.) before delivery.
- External (SBC) mode: lighttpd serves the same files; `hotspot/js/varbridge.js` detects literal `$(...)` tokens in the DOM, exposes a `window.PORTAL` object with query params (`mac`, `ip`, `user`, `login`, `logout`, `err`) and helper URL builders (`statusUrl`, `loginUrl`), then patches the DOM by stripping `$(if ...)/$(endif)` markers, substituting tokens in text nodes and attributes, and wiring form actions to the router's real login URL.
- `hotspot/api.json` is a MikroTik template fragment consumed by the router's redirect chain to advertise captive-portal capabilities and remaining session bytes/time.
- `api/session.php` is a standalone, unauthenticated JSON endpoint (`GET ?mac=...`) that queries enabled routers through the shared `includes/RouterOS/RouterFactory` and returns `{connected, user, uptime, bytes_in, bytes_out, time_left}` for the status page to poll. It opens CORS (`Access-Control-Allow-Origin: *`) intentionally because it only reports the caller's own MAC.
- Static assets under `hotspot/assets/` (Bootstrap, jQuery, qrcode, pako, toast) are bundled client-side; `hotspot/xml/` holds MikroTik WISP schema and alternate login/logout/error templates used by the router's native flow.
